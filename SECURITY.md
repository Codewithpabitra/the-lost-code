# Security Policy

## The Lost Code

The security of **The Lost Code** and its users is important.

We appreciate responsible security researchers and developers who help identify vulnerabilities and improve the security of this project.

## Supported Versions

Security fixes and vulnerability assessments are focused on the latest available version of the project.

| Version                    | Security Support |
| -------------------------- | ---------------- |
| Latest development version | Supported        |
| Older versions             | Not supported    |

## Reporting a Vulnerability

If you discover a potential security vulnerability, please report it responsibly.

**Please do not disclose vulnerabilities through public GitHub issues, discussions, or pull requests.**

Instead, use one of the following methods:

1. If GitHub Private Vulnerability Reporting is enabled, use the repository's **Security → Report a vulnerability** option.
2. If private reporting is unavailable, contact the project maintainer through their GitHub profile:
   https://github.com/Codewithpabitra

Include the following information in your report:

- A clear description of the vulnerability.
- The affected component or endpoint.
- Steps to reproduce the issue.
- Potential security impact.
- Screenshots, logs, or proof of concept, if applicable.
- Suggested mitigation, if known.

Please avoid including real user data, passwords, API keys, or other sensitive information in your report.

## Responsible Disclosure Guidelines

To help protect users and the project, please:

- Give the maintainer reasonable time to investigate and address the issue before public disclosure.
- Do not exploit vulnerabilities beyond what is necessary to demonstrate them.
- Do not access, modify, or delete other users' data.
- Do not perform denial-of-service attacks or disruptive testing.
- Do not publicly share vulnerability details before a fix or an agreed disclosure date.

## Response Process

After receiving a valid report, the maintainer will make reasonable efforts to:

1. Acknowledge the report.
2. Review and validate the reported vulnerability.
3. Assess its severity and potential impact.
4. Develop and release an appropriate fix where necessary.
5. Coordinate disclosure with the reporter when appropriate.

Response and resolution timelines may vary depending on the complexity and severity of the issue.

## Scope

Security reports may include vulnerabilities affecting:

- Authentication and authorization.
- API endpoints and backend services.
- Database access and data exposure.
- Session management and token handling.
- Input validation and code evaluation.
- Sensitive information and environment configuration.
- Dependencies and deployment configuration.

## Recognition

We appreciate responsible disclosures that help make The Lost Code safer.

Recognition is not guaranteed and is provided at the maintainer's discretion.
